# 界面设计规范

> 本目录是 CRP 提测平台的界面唯一基准。`prototype.html` 是可交互原型，本文件是它的文字化规格。
>
> **改界面前先读这里，改完同步更新 `prototype.html`。** 两者不一致时以 `prototype.html` 为准，并把本文件补齐。

## 一、这份文档解决什么问题

功能全部满足、CI 全绿、每轮验收都通过，界面却和原型差了一整套视觉语言，而没有任何一道门禁能发现。根因不是执行，是流程缺了「设计基准」这一环：没有基准，验收就只能验功能。

所以本目录同时承担三件事：

1. **设计基准**：颜色、布局、组件、页面结构，全部写成可核对的数字。
2. **验收依据**：QA 逐页对照 `prototype.html`，不是凭感觉。
3. **变更入口**：任何 UI 讨论先改原型，同意后再动代码。

## 二、产品与用户

| 项 | 内容 |
| --- | --- |
| 产品 | CRP 提测平台（Release Hub），统信桌面研发内部工具 |
| 用户 | 研发、项目经理、QA。每天开几次，每次看几十条提测与构建状态 |
| 单屏任务 | 判断「哪个包卡住了、下一步点哪里」 |
| 使用环境 | 桌面浏览器为主，1280 起；窄屏（375）要能看，但不作为主场景 |
| 情绪目标 | 稳定、可扫读、不喧宾夺主 |

**这不是消费产品，是控制台。** 界面的价值在于让人快速定位异常，不在于好看。

## 三、五条设计原则

按重要性排序，冲突时上面的赢。

1. **状态是唯一允许用饱和色的地方。** 其余部分退到背景。一屏里最跳的应该是「失败的包」。
2. **靠留白与 1px 浅线分层，不靠阴影。** 卡片阴影只到 `0 2px 7px rgba(35,50,75,.025)`，几乎看不见。
3. **深色侧栏压住画面。** 侧栏是骨架，不是装饰。它让内容区的白卡片浮起来。
4. **密度优先，但不牺牲可点。** 表格 13px、表头 12px；可交互元素命中区 ≥40px。
5. **不加动效。** 高频操作装动效等于拖慢。只保留按下反馈与键盘焦点环。

## 四、布局系统

### 4.1 骨架

```
┌────────────┬──────────────────────────────────────────┐
│            │  page-header                             │
│  sidebar   │  ┌ h1 页面名 ──────────── 主操作按钮 ┐    │
│  232px     │  └ 一句话说明 ──────────────────────┘    │
│  深色      ├──────────────────────────────────────────┤
│            │  view（内容区，最大宽 1440，居中）        │
│  - 品牌    │  ┌ section ────────────────────────────┐  │
│  - 导航    │  │ h2 分组标题 + hint                  │  │
│  - 账号区  │  │ ┌ card ───────────────────────────┐ │  │
│  （底部）  │  │ │ 表格 / 表单 / 列表               │ │  │
│            │  │ └─────────────────────────────────┘ │  │
│            │  └─────────────────────────────────────┘  │
└────────────┴──────────────────────────────────────────┘
```

| 项 | 值 |
| --- | --- |
| 侧栏宽 | 232px（`--sidebar-w`） |
| 内容最大宽 | 1440px（`--content-max`），超出居中 |
| 页头内边距 | 上 24 / 左右 32 / 下 16 |
| 内容区内边距 | 左右 32 / 下 48 |
| 侧栏 `position` | `sticky; top: 0; height: 100vh`，导航自己滚，账号区靠 `margin-top:auto` 顶到底 |

### 4.2 间距刻度

只有七档，不许自造。

| token | 值 | 典型用途 |
| --- | --- | --- |
| `--s1` | 4px | 图标与文字之间 |
| `--s2` | 8px | 按钮组、行内元素 |
| `--s3` | 12px | 卡片之间、字段之间 |
| `--s4` | 16px | 卡片内边距、页头下边距 |
| `--s5` | 24px | 页头上边距、卡片内边距（宽松） |
| `--s6` | 32px | 分组之间、页头左右 |
| `--s7` | 48px | 内容区底部、危险区上边距 |

### 4.3 响应式断点

| 断点 | 行为 |
| --- | --- |
| > 1100px | 完整布局；统计卡 4 列 |
| 760–1100px | 侧栏保持；统计卡 2 列；页头与内容区内边距降到 16 |
| ≤ 760px | 侧栏变横向导航条（品牌 + 图标），账号区隐藏；统计卡 2 列（原型 `@media(max-width:720px)` 为 `.stats{1fr 1fr}`，此处按「以 prototype.html 为准」补齐）；页头竖排 |

**硬约束**：任何断点下 `document.scrollingElement.scrollWidth <= clientWidth`。宽表在自己的 `.table-scroll` 容器里滚，不允许整页横滚。

注意这一条只是必要条件：`minmax(0, …)` 的栅格在窄屏会把列压到 0 宽而不是溢出，所以验收还要查实际列宽（例如 `.two-col` 的子项 ≥280px、`.stat` ≥140px）。

## 五、颜色

### 5.1 定稿 token

全部按 WCAG 2.1 相对亮度公式算过。**正文文字 ≥4.5:1，控件边框 ≥3:1**。

| 角色 | 值 | 对比度 | 用途 |
| --- | --- | --- | --- |
| 画布 | `#f5f7fa` | — | body 背景 |
| 卡片面 | `#ffffff` | — | 卡片、表格、表单 |
| 弱面 | `#fafbfc` | — | 表头、行 hover |
| 装饰线 | `#e8edf2` | 1.18:1 | 卡片边、分隔线。**只做装饰，不承载信息** |
| 控件边框 | `#868c95` | 3.39:1 on white | 输入框、下拉、次要按钮描边 |
| 正文 | `#202b3c` | 14.26:1 | 主体文字 |
| 次要文字 | `#5d6875` | 5.67 / 5.28 | 说明、hint、表头 |
| 更弱提示 | `#6f757f` | 4.64:1 | 元信息、`secondary` |
| 主色 | `#3269e8` | 4.86:1 | 主按钮、链接、选中态 |
| 主色浅底 | `#edf3ff` | — | 选中行、信息 pill 底 |
| 侧栏底 | `#172338` | — | 侧栏 |
| 侧栏文字 | `#aab7ca` | 7.75:1 | 未选中导航 |
| 侧栏选中底 | `#2d57a8` | 白字 6.91:1 | 当前页导航 |
| 成功 | `#0f6b4a` / `#eaf8f1` | 5.96:1 | 提测成功、构建成功 |
| 失败 | `#b0363d` / `#fff0f0` | 5.51:1 | 构建失败 |
| 警告 | `#8a5b12` / `#fff5e8` | 5.43:1 | 限流等待、风险 |
| 信息 | `#2a5ac4` / `#edf3ff` | 5.62:1 | 投递中、构建中 |
| 中性 | `#4f5866` / `#f1f3f6` | 6.47:1 | 待投递、排队中 |

### 5.2 使用规则

- **一种颜色只表示一件事。** 绿永远是成功，红永远是失败，橙永远是警告，蓝永远是进行中。
- **装饰线与控件边框是两个 token，不许混用。** 前者 1.18:1 只做视觉分隔，后者 3.39:1 用来标识可交互边界。
- **状态不能只靠颜色传达。** pill 必须带文字，图标必须带标签。
- **禁止**：渐变文字、玻璃拟态、彩色粗边条（>2px）、`transition: all`。

### 5.3 为什么不能照抄原型的颜色

原型里这几处不达标，已替换，不要改回去：

| 位置 | 原型值 | 对比度 | 定稿值 |
| --- | --- | --- | --- |
| 次要文字 | `#758195` | 3.94 / 3.67 | `#5d6875` |
| 更弱提示 | `#9aa4b2` | 2.52 | `#6f757f` |
| 侧栏分组标签 | `#74849c` | 4.14 | `#8b9ab1` |
| 表头 | `#8b96a7` | 2.89 | `#5d6875` |
| 成功 pill | `#16845f` | 4.27 | `#0f6b4a` |
| 失败 pill | `#c74f56` | 4.05 | `#b0363d` |
| 信息 pill | `#376bd8` | 4.43 | `#2a5ac4` |

## 六、排版

| 角色 | 字号 / 行高 / 字重 |
| --- | --- |
| 正文 | 14px / 1.6 / 400 |
| 表格 | 13px / 1.5 / 400 |
| 表头 | 12px / 1.4 / 600，次要色 |
| h1（页面名） | 22px / 1.25 / 650，`letter-spacing: -.2px` |
| h2（分组） | 16px / 1.4 / 600 |
| h3 | 14px / 1.4 / 600 |
| hint（一句话说明） | 12.5px / 1.6 / 400，次要色，`max-width: 78ch` |
| 标识符 | 等宽栈 + `font-variant-numeric: tabular-nums` |

**标识符一律等宽**：版本号、提交号、Topic ID、仓库路径。这些是运维要逐字比对的东西，比例字体对不齐。

**中文不做字距调整**，不做全大写（中文没有大小写，`text-transform: uppercase` 只对英文生效，会造成中英混排不一致）。

## 七、模块清单（来自原型，不许改名、不许合并、不许降级）

**这一节是最重要的约束。** 原型的页面由下面这些模块拼成，实现必须沿用同一套 class 名与 DOM 结构，只替换不达标的颜色值。

前一版 `design.md` 把这些模块「提炼」成了通用组件（表格、卡片、徽标），结果是颜色对了、模块全丢了。**提炼是错的，移植才对。**

| 模块 | 用途 | 出现页面 |
| --- | --- | --- |
| `.manager-grid` / `.manager-card` | 项目经理卡：头像、姓名、工作区、名下项目数 | 项目 |
| `.project-grid` / `.project-card` | 项目卡：类型图标、名称、标识、经理、基线、软件数、依赖数、软件清单 chips | 项目、提测详情 |
| `.project-software-chips` | 软件清单 chips，带顺序号与「依赖 N 项 / 无依赖」 | 项目 |
| `.dep-flow` / `.dep-row` | 依赖拓扑：竖向串联，序号节点 + 软件名 + 上游说明 + 状态 | 构建队列 |
| `.queue-list` / `.queue-item` | 队列条目：图标、软件包、说明、进度条（`.progress`）、耗时或依赖 | 工作台、构建队列 |
| `.stats` / `.stat` / `.stat-ico` | 统计卡：标签、数值、提示、右侧图标块 | 工作台、构建队列 |
| `.page-tabs` | 状态页签（全部 / 构建中 / 成功 / 失败） | 提测记录 |
| `.filters` / `.search-field` | 筛选条与搜索框 | 提测记录、项目 |
| `.summary-strip` / `.summary-cell` | 详情页概要条：4 格带竖分隔线 | 提测详情 |
| `.timeline` / `.tl-item` | 版本关系时间线：圆点 + 内容 | 提测详情 |
| `.tip` | 提示块：图标 + 标题 + 正文 | 工作台、构建队列、项目、Webhook、CRP 接入、详情 |
| `.risk-box` | 风险标记框 | 提测详情（风险版本） |
| `.section-title` | 分组标题行：标题 + 右侧说明或操作 | 项目、提测详情 |
| `.table-scroll` | 宽表滚动容器。单独用时带 1px 装饰线与 8px 圆角；嵌在 `.card`（面板或 `.table-card`）里时由卡片收边，容器只负责横向滚动 | 各列表页 |
| `.empty` | 空状态 | 工作台、提测记录、提测详情 |
| `.modal` | 弹窗：头、体、脚，宽版 1120 | 创建提测、编辑项目、依赖配置、导入 |
| `.toast` | 右下角轻提示 | 全局 |

### 使用规则

- **一个模块一个职责。** 不要把 `.project-card` 降级成表格行，也不要把 `.dep-row` 拼进表格单元格。
- **模块内的信息顺序照原型。** 例如项目卡是「图标 + 名称 → 经理/工作区 → 三项 meta → 软件 chips → 说明 + 标签」。
- **class 名不改。** 实现里已有的通用组件（`.data-table`、`.badge`、`.alert`、`.filter-bar`）可以保留给新场景，但**不能用来替代原型模块**。
- **模块名以 `modules.json` 为准。** 原型里同一个位置的 class 与 `modules.json` 不一致时（例如原型写 `.table-wrap`、清单写 `.table-scroll`），实现两个名字都挂上，以清单里的名字为模块名 —— `pnpm check:modules` 只认清单。
- **进度条用真实比例。** `.progress` 用原生 `<progress value max>`，值来自 `lib/build/queue.ts` 的作业计数；不照抄原型里硬编码的 `68%`，也不写内联 `style`。
- **`.stat` 的趋势行（原型里的 `.up`）不要求实现。** 数据层没有环比，照抄「↑ 16.7%」就是编数字；第三行 `.hint` 写真实口径即可。

## 八、九个页面的模块构成

每页的模块组合照下表。这是「模块划分」的定义，不是建议。

| 页面 | 模块 |
| --- | --- |
| 工作台 | `.stats`（4 个 `.stat` 含 `.stat-ico`）→ 最近提测表 → `.queue-list` + `.tip` → 项目概况表 → 配置概况 `.queue-list` + `.empty` |
| 提测记录 | 页头动作 → `.page-tabs` → `.filters` + `.search-field` → `.table-scroll` 表格 → 表尾说明 → `.empty` |
| 提测详情 | `.summary-strip`（4 个 `.summary-cell`）→ 仓库记录表 → 软件快照表 → `.project-card` 概要 → `.timeline` → `.risk-box`（条件）→ `.tip` |
| 项目 | `.section-title` 项目经理 → `.manager-grid` → `.section-title` 项目列表 → `.filters` → `.project-grid` → `.section-title` 软件包管理 → 软件包表 + `.tip` |
| 软件包 | 登记表（名称 / 仓库 / CRP 项目名 / 分支 / 版本 / Commit / 依赖 / 引用）→ `.tip` |
| 基线 | 分支清单表（分支 / 说明 / IsCheck / 包数 / 架构 / 同步）→ `.tip` |
| 构建队列 | `.stats` → `.dep-flow` + `.tip` → `.queue-list` → 调度事件表 |
| Webhook 端点 | 端点卡列表 → 事件订阅说明 → `.tip` → 投递日志表 |
| 项目经理 | `.manager-grid` → 清单表 |

**通用骨架**：`页头（h1 + 一句话说明 + 主操作）→ 若干 section`。section 之间用 `--s6` 间距，section 内标题用 `.section-title` 或 `h2 + hint`。

## 九、交互与动效

- **不加动效。** 只保留：`:active` 的 `scale(.96)`、`:focus-visible` 的 2px 焦点环、`transition: background .12s`。
- 破坏性操作（放弃主题、取消提测）必须二次确认，确认框写清影响范围与「不可撤销」。
- 加载中要有静态占位，不能白屏。
- 错误写在界面里，不用 `alert`。

## 十、无障碍底线

| 项 | 要求 |
| --- | --- |
| 正文对比度 | ≥4.5:1（大字 ≥3:1） |
| 控件边框对比度 | ≥3:1 |
| 命中区 | ≥40×40px（密集桌面界面下限） |
| 键盘 | 所有交互可 Tab 到达，焦点环可见 |
| 语义 | 状态不只靠颜色；图标按钮有 `aria-label` |
| 缩放 | 200% 缩放下不出现整页横滚 |

## 十一、怎么验收

1. **模块对照（硬判据）**：打开 `.agents/spec/design/prototype.html`，逐页比对 class 清单。原型有的模块，实现里必须有；缺一个即不通过。只看颜色对、模块不对的，判不通过。
2. 打开原型，逐页对照布局、信息顺序、交互。
3. 跑 `pnpm test:style`（样式门禁），退出码必须 0。
4. 跑对比度审计脚本，失败必须 0 处。
5. 四档宽度（375 / 768 / 1280 / 1440）逐页确认无整页横滚。
6. 结论写进 issue 的 `[Result]`：哪些页面一致、哪些不一致、不一致是否已确认。

**只跑功能 AC、不做原型对照的验收，判不通过。**

## 十二、变更流程

1. 任何 UI 讨论，**先改 `prototype.html`**，在 issue 里贴出改动前后对照。
2. 涉及 UI 的 PR **必须 @ lxz 确认**，没有明确确认不允许合并。这条优先于「CI 全绿」「评审通过」「QA 通过」。
3. 原型与实现同时改，同一个 PR 里完成。
4. 改完同步更新本文件的 token 表与模块清单。
5. **禁止「提炼」原型。** 把原型的模块概括成「通用卡片」「通用表格」再让实现去猜，是上一轮 UI 走样的根因。原型怎么写，实现就怎么搬。

## 十三、已知取舍

- **深色侧栏 + 浅色画布是常见后台形态**，不是独创。选它的理由是产品原型已经这么定，且它服务于「状态色要跳出来、其余退到背景」这个具体判断。
- **不做暗色主题**：v1 未要求，做了就要维护两套对比度。
- **不做动效**：高频操作下动效是负担，不是精致。
- **表格 13px 已经偏小**：再小会影响可读性，密度靠列宽与留白调，不靠缩字号。
