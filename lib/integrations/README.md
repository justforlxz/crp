# 外部系统集成模块

本目录存放与外部系统通信的客户端。当前节点不实现任何调用，这里只固定三个模块的职责边界，避免后续把外部接口逻辑散落到页面与 Route Handler 里。

| 模块 | 对应系统 | 负责 | 不负责 |
| --- | --- | --- | --- |
| `crp` | CRP（`https://crp.uniontech.com/api`） | 登录与会话保持、基线列表、建 Topic、`new_release` 投递、Release 查询/删除/重试、仓库地址查询 | 判定投递顺序、跟踪构建结果、写提测状态 |
| `shuttle` | Shuttle（`https://shuttle.uniontech.com/api/shuttle`） | 基线仓库内软件包版本查询、构建任务列表与构建日志 | 决定提测内容、修改提测快照 |
| `gerrit` | Gerrit | 分支列表、提交列表与单条提交、按提交读取 `debian/changelog` | 解析提测版本规则、与 CRP 交互 |

共同约定：

- 客户端只做「调用 + 返回结构化数据」，不直接写数据库；写库由 `lib/` 下的领域逻辑完成。
- 凭据一律来自环境变量，模块内不出现常量形式的账号、密码、Token。
- 网络错误、鉴权失败、接口返回异常由客户端转换为带上下文的错误抛出，由调用方决定是否重试。
- 每个模块接入真实接口时，都要把请求与响应的证据写进对应节点的 `FINDINGS` 文档。
