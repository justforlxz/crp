# CRP 与 Gerrit 凭据契约

## 一、为什么有这份文档

平台的每一次 CRP 调用都会在 CRP 侧留下操作人和时间。如果全平台共用一个账号，CRP 上看到的提交人永远是同一个人，「谁提的、谁批的」这条审计链就断了，而这正是本平台存在的意义。同一个问题也发生在 Gerrit 上：查代码状态用的是共用账号，就查不到「这个人有没有权限看这个分支」。

结论：**凭据按人存放，按当前操作人使用**，环境变量里不再出现任何个人凭据。

## 二、现状（改造前）

| 项 | 现状 |
| --- | --- |
| 凭据来源 | 进程环境变量 `CRP_USERNAME` / `CRP_PASSWORD`、`GERRIT_USERNAME` / `GERRIT_HTTP_PASSWORD` |
| 读取位置 | `lib/integrations/crp/config.ts` 的 `readCrpConfig()`、`lib/integrations/gerrit/client.ts` |
| 数据库 | 没有任何存凭据的表 |
| 登录令牌 | CRP 的 token 缓存在 `~/.cache/crp/jwt` 一个固定文件，所有人共用 |
| 后果 | 审计身份丢失、权限越界、一个人改密码全平台挂 |

## 三、目标

1. 每个成员在 Web 上配置自己的 CRP 账号与 Gerrit 账号。
2. 平台以**当前操作人**的身份调 CRP 与 Gerrit。
3. 后台作业以**数据所有者**的身份调用。
4. 环境变量里只剩平台自己的密钥，不再有任何个人凭据。

## 四、数据模型

新增一张表 `UserCredential`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | text，主键 | |
| `userId` | text，外键指向 `app_user` | 凭据属于谁 |
| `kind` | 枚举 `crp` / `gerrit` | 哪一套系统 |
| `username` | text | 账号名，明文存，用于展示 |
| `secretCiphertext` | text | 密码密文，AES-256-GCM |
| `secretIv` | text | 初始向量 |
| `secretTag` | text | 认证标签 |
| `keyVersion` | int | 主密钥版本，用于轮换 |
| `verifiedAt` | 时间戳，可空 | 最后一次验证成功的时间 |
| `lastError` | text，可空 | 最后一次验证失败的原因 |
| `createdAt` / `updatedAt` | 时间戳 | |

唯一约束：`(userId, kind)`。一个人每种系统只能有一份凭据。

**明文密码永不入库、永不出接口。** 接口只返回「是否已配置、账号名、最后验证时间、最后错误」。

## 五、加密

- 算法 AES-256-GCM。
- 主密钥从环境变量 `CREDENTIAL_ENCRYPTION_KEY` 读，32 字节，base64 编码。这是唯一保留的环境变量，它是平台密钥，不是某个人的凭据。
- AAD 绑定 `userId + kind`，防止把 A 的密文挪到 B 名下继续用。
- 解出来的明文只在内存里存活到这次调用结束，不写日志、不进错误信息。
- 主密钥缺失时，凭据相关接口直接报「服务端未配置加密密钥」，不降级、不回退到环境变量。

## 六、调用身份

| 场景 | 用谁的身份 |
| --- | --- |
| 页面操作、前台接口（创建提测、投递、刷新代码状态、查 Topic） | 当前登录用户 |
| 后台作业 `build-poll` | **该提测的创建者**（`release.created_by_id`） |
| 后台作业 `build-dispatch` | 该提测的创建者 |
| 后台作业 `baseline-sync` | 不需要凭据，CRP 分支列表接口匿名可读 |
| Webhook 投递 | 平台自身，不走用户凭据 |

创建者的凭据已被删除或验证失败时：作业记一条明确的失败原因并跳过这一条，不阻塞其他提测的处理，也不静默成功。

## 七、令牌缓存

CRP 的登录令牌**按人分别缓存**，不能共用一个文件：

- 首选：只放进程内存，按 `userId` 分键，过期重新登录。令牌有效期短，落盘收益低、泄露风险高。
- 若必须落盘：路径包含 `userId`，文件权限 0600，且不能落在仓库目录。

## 八、页面

新增「我的账号」页，路由 `/settings/credentials`。

| 区块 | 内容 |
| --- | --- |
| CRP 账号 | 用户名、密码、「保存并验证」；已配置时显示账号名与最后验证时间，可「更新」或「删除」 |
| Gerrit 账号 | 用户名、HTTP Password、「保存并验证」；同上 |
| 未配置说明 | 明确写出哪些功能不可用：创建提测、投递构建、刷新代码状态 |

**保存时必须先真实验证再入库**：用这组凭据真实登录一次 CRP、真实请求一次 Gerrit。验证失败不入库，把失败原因原样显示。

## 九、未配置时的行为

- 创建提测、投递、刷新代码状态：直接给出「请先在「我的账号」配置 CRP 账号」并附页面链接。
- 不静默失败，不退回环境变量里的旧账号。

## 十、迁移

1. 新增表与迁移。
2. 环境变量 `CRP_USERNAME`、`CRP_PASSWORD`、`GERRIT_USERNAME`、`GERRIT_HTTP_PASSWORD` 从 `.env.example`、RUNBOOK、CI 配置里删除。
3. 保留 `PACKAGE_API_TOKEN`、三个作业 token、`CREDENTIAL_ENCRYPTION_KEY`。
4. 现有共用账号的使用者需要在「我的账号」里各自配置一次。

## 十一、风险

| 风险 | 处理 |
| --- | --- |
| 主密钥丢失，所有凭据不可解密 | RUNBOOK 写明主密钥的备份与轮换步骤；`keyVersion` 支持新旧密钥并存 |
| 加密密钥泄露 | 密钥只在服务端环境变量，不进仓库、不进镜像、不打印 |
| 后台作业因创建者缺凭据而停更 | 作业结果里列出被跳过的提测与原因，页面上对应的提测显示「构建状态停更」 |
| 用户填错密码 | 保存时先验证，不通过不入库 |

## 十二、验收

| 编号 | 验收内容 | 验证方式 | 通过条件 |
| --- | --- | --- | --- |
| CRED-1 | 明文不入库 | 配置一份凭据后直接查表 | 表中只有密文，搜索不到明文 |
| CRED-2 | 接口不回传密码 | 请求 `/api/settings/credentials` | 响应里没有密码字段 |
| CRED-3 | 保存前验证 | 填一个错误密码点保存 | 返回失败原因，表里没有新增记录 |
| CRED-4 | 按人调用 | A、B 各配一份，各自创建提测 | CRP 侧两次操作的操作人分别是 A、B |
| CRED-5 | 后台作业用创建者身份 | 触发 `build-poll` | CRP 侧查询操作人等于该提测创建者 |
| CRED-6 | 未配置的拦截 | 未配置的用户点创建提测 | 提示去配置页，不发送任何 CRP 请求 |
| CRED-7 | 环境变量已移除 | `grep CRP_USERNAME` 全仓 | 只剩文档里的迁移说明 |
| CRED-8 | 密文不可跨人挪用 | 把 A 的密文复制到 B 的记录上再解密 | 解密失败（AAD 校验不通过） |
