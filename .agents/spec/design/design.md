# 界面设计规范（v2）

## 一、这份文档的地位

- **`.agents/spec/design/prototype.html` 是唯一依据。** 它是可交互原型，所有页面、所有状态都在里面。
- 本文把原型里的数字、类名、流程写成可核对的清单。**两者冲突时以原型为准**，并回头改本文。
- `.agents/spec/design/modules.json` 是机器可读的模块清单，`pnpm check:modules` 按它比对实现。

改界面之前必须读完这三份。不要凭感觉设计，不要另起一套视觉语言。

## 二、产品与用户

| 项 | 内容 |
| --- | --- |
| 产品 | CRP 提测平台（Release Hub），统信桌面研发内部工具 |
| 用户 | 研发、项目经理、QA。每天开几次，每次看几十条提测与构建状态 |
| 单屏任务 | 判断「哪个包卡住了、下一步点哪里」 |
| 使用环境 | 桌面浏览器为主，1280 起；375 要能看不溢出，但不作为主场景 |
| 情绪目标 | 稳定、可扫读、不喧宾夺主 |

**这是控制台，不是消费产品。** 界面的价值在于让人快速定位异常。

## 三、设计方向

「工程控制台」：深墨侧栏压住画面，浅灰画布上浮白卡片；层级只靠 1px 线与留白，不用厚阴影；数字统一等宽；状态一律「色点 + 文字」。

三条不可动摇：

1. **状态色只用在状态上。** 一屏里最跳的应该是失败的包，不是装饰。
2. **页面标题住在顶栏。** 内容区不再重复一个大标题，省掉每页先读一段废话。
3. **表格与卡片共用一套容器语言。** 12px 圆角 + 1px `#e3e8ef` 描边 + 几乎看不见的阴影。

### 4.1 间距刻度

**只用 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 这八档。** 区块之间 20px，卡片内 16px，表单行之间 16px。

允许两个例外，除此之外任何值都算错：

| 例外 | 值 | 为什么 |
| --- | --- | --- |
| 1px 分隔线与边框 | 1px | 它表达结构，不是间距 |
| 胶囊与极小文字的微调 | 2px | 胶囊纵向、`.cell-sub` 上边距，超过 2px 就必须落到刻度上 |

**禁止出现的值：5、6、10、13、14。** 这几个值曾经遍布原型（`.chip` 间距 5、`.btn` 图标间距 6、`.tip` 间距 10、`.pc-facts` 外边距 13、表格与按钮的 14），一屏里出现八个档位，看上去「对齐了但不对得干净」。

判定方法：在浏览器里遍历元素，读计算后的 `padding` / `margin` / `gap`，凡是不在八档之内且不在例外表里的值，都算越界。

### 4.2 圆角的同心关系

外层圆角 = 内层圆角 + 内边距。当前取值：卡片 12、卡片内图标块 10、小图标块 6、胶囊 20（全圆）、提示块 8。嵌套时按这个关系算，不要两层都用 12。

响应式断点：

| 断点 | 变化 |
| --- | --- |
| ≤1180px | 统计卡与详情概要条降为 2 列；详情页双栏变单栏 |
| ≤900px | 侧栏变 60px 图标栏；顶栏说明隐藏；内容内边距降为 16 |
| ≤680px | 全部单列；筛选条竖排；步骤条文字隐藏 |

### 使用规则

- **一个模块一个职责。** `.project-card` 不能降级成表格行；`.dep-row` 不能塞进表格单元格；`.timeline` 不能换成普通列表。
- **类名不改。** 已有的通用类（`.btn`、`.grid`、`.num`）可以复用，但不能替代上面的模块。
- **模块内的信息顺序照原型。** 例如项目卡是「图标 + 名称 → 三项事实 → 软件胶囊 → 底部操作」。
- **新增模块要先进原型。** 实现里需要原型没有的结构时，先改原型，再加进 `modules.json`。

## 八、提测流程契约

**创建提测固定三步，顺序和每步的内容不允许改。** 详细字段见原型 `openWizard`。

| 步骤 | 名称 | 内容 | 底部按钮 |
| --- | --- | --- | --- |
| 1 | 项目归属 | 项目经理下拉、所属项目下拉（跟随经理联动）、5 格基线摘要（目标系统仓库 / 项目 CRP 基线 / 基线同步状态 / 项目固定软件 / 项目经理）、CRP 提测版本号、项目类型（只读）、提测说明 | 取消 / 检查项目仓库更新 → |
| 2 | 检查仓库更新 | 目标基线横幅 + 预设仓库数；Gerrit 代码状态区带三档统计（关注仓库 / 检测到更新 / 无变化）与刷新按钮；筛选（全部 / 仅有更新 / 仅无变化）+ 搜索；7 列表格（提交顺序、软件仓库、本次分支、本次 Commit 与代码版本、CRP 仓库版本、本次提测版本、更新状态）；每行可切分支、选历史 Commit、设自定义版本号；表尾统计 | 上一步 / 确认版本信息 → |
| 3 | 确认提测 | 三组配置摘要；「本次提测版本确认」7 列表格；确认提示块 | 返回调整版本 / 在目标 CRP 基线上创建提测 |

### 四条必须保持的语义

1. **项目固定软件清单全部提测。** 不让用户勾选要提测哪几个包。项目边界就是提测边界。
2. **提交顺序来自软件包依赖。** 用户不能排，也不能拖。
3. **更新状态只作提示。** 「无变化」的包也保留在清单里，不决定是否纳入。
4. **每个软件可切分支、选历史 Commit、设自定义版本号。** 自定义版本只覆盖本次提测的仓库版本，不改代码版本。

### Gerrit 下拉的禁用规则

第 2 步的分支与 Commit 下拉来自 Gerrit 实时查询：

- 查询成功：下拉可用，选项是真实分支与真实 Commit。
- 查询失败或超时：**下拉禁用并显示原因**，不允许填入任何占位或猜测值。
- 没有任何候选：下拉禁用并提示「该软件包没有可用分支」。

不得用假数据兜底。原型里的选项是演示数据，实现里必须是真实查询结果。

## 九、交互契约

| 交互 | 行为 |
| --- | --- |
| 侧栏切换 | 换页并更新顶栏标题、说明、主操作；滚到顶部 |
| 工作区切换 | 工作台与提测记录页各有一个工作区下拉（`.filters` + `.select`）；切换后当前页的统计与列表只反映该工作区 |
| 页签切换 | 过滤表格行；页签上显示各状态的真实计数 |
| 搜索 | 输入即过滤；结果数写在筛选条右侧 |
| 无结果 | 显示 `.empty`，带一个「清除筛选」动作 |
| 点表格行 | 进入该条提测详情 |
| 点项目卡 | 打开「编辑项目」弹窗（名称、标识、项目经理、基线、说明），保存后卡片当场更新 |
| 项目卡「...」 | 打开操作菜单：编辑项目 / 软件包清单 / 发起提测 / 复制项目 / 删除项目 |
| 软件包清单 | 弹窗内增删包；**顺序由软件包依赖算，不按添加顺序**，用户不能拖 |
| 项目卡「发起提测」 | 打开三步向导并预选该项目所属经理与项目 |
| 项目经理卡（项目页） | 按该经理筛选项目列表；再点一次清除筛选 |
| 项目经理卡（项目经理页） | 打开「编辑项目经理」弹窗 |
| 软件包行 | 打开「编辑软件包」弹窗（deb 包名、CRP 项目名、仓库路径、跟踪分支、版本） |
| Webhook「编辑」/「新增端点」 | 同一个弹窗表单，订阅事件用 `.pick` 多选，不用裸 checkbox |
| 删除类操作 | 一律二次确认，文案写清「只删平台配置，不动 CRP」 |
| 详情返回 | 回到提测记录列表 |
| 打开向导 | 重置为第 1 步，清空已选 |
| 向导下一步 | 当前步必填项没选时按钮禁用，不弹错 |
| 自定义版本号 | 在单元格内展开输入框，保存 / 恢复默认 / 取消；设过的值在第 3 步标「自定义 Tag」 |
| 破坏性操作 | 二次确认，文案写清影响范围与「不能撤销」 |
| 轻提示 | 操作成功后右下角出现，4.2 秒消失，可叠加 |
| 关闭弹窗 | 点右上角 ×、点遮罩空白处、按 Esc，三种都要生效 |
| 按压缩放 | 所有可点元素按下时 `scale(.97)`；这是唯一的动效 |

**不加动画。** 不做过场、不做淡入、不做骨架屏以外的动效。高频操作装动效等于拖慢。

## 十、无障碍底线

- 正文文字对比度 ≥ 4.5:1，控件边框 ≥ 3:1。上表的数值是实测值，改色必须重新测。
- 可交互元素命中区 ≥ 40px。视觉尺寸小于 40 时用伪元素扩展，不靠放大留白。
- 键盘焦点必须有 2px 焦点环（`--accent`，偏移 2px）。
- 表格表头用 `<th>`，表单控件必须有 `<label>`。
- 不用颜色单独表达状态：色点旁边必须有文字。

## 十一、响应式

- 1280 与 1440 是主场景，两者都不允许出现横向溢出。
- 375 宽必须九页全部无横向溢出；表格在 `.table-scroll` 内横向滚动，页面本身不滚。
- 网格容器用 `minmax(min(340px, 100%), 1fr)` 这种写法，避免窄屏被最小宽度顶破。

## 十二、验收与门禁

界面相关的任务必须同时满足：

1. `pnpm check:modules` 报 9 个页面齐备、全局齐备、样式表齐备。
2. `.agents/spec/design/test-cases.md` 里的界面用例全部执行并通过。
3. 逐页对照原型：模块存在且结构没降级。类名存在但结构降级判不通过。
4. 涉及 UI 的 PR 必须经 lxz 确认才能合并。这条优先于「CI 全绿」「评审通过」「QA 通过」。

## 十三、变更流程

1. 先改 `prototype.html`，在 issue 里说明理由，等确认。
2. 同步改 `design.md` 的参数表与模块清单。
3. 同步改 `modules.json`。
4. 最后才动实现。

反过来的顺序（先改代码再补文档）一律不接受。

## 十四、已知取舍

- **原型里的数据是编的。** 提测条数、Commit、分支都是演示值；实现里必须来自真实查询。
- **不加动画。** 只有按压缩放与焦点环。
- **无暗色主题。** 当前不做，也不预留变量。
- **详情页的风险框条件渲染。** 没有风险时不渲染，不留空壳。
- **统计卡不做环比。** 数据层没有环比，写出来就是编数字。
- **工作台的工作区下拉是原型初版漏画的，已补进原型。** 工作台的统计、最近提测与项目概况都按工作区隔离，切工作区必须能在这一页完成；实现用的是提测记录页那套 `.filters` + `.select`，没有新增模块或样式（`prototype.html` 工作台节的 `.stack` 第一行、MKACG-983）。
