# 运行与环境契约

## 一、数据政策

**只允许测试环节与原型设计使用 mock。部署给人用的实例必须是实机数据。**

| 环境 | 允许 mock / 种子数据 | 说明 |
| --- | --- | --- |
| 单元测试、CI、界面截图门禁 | 允许 | 需要确定性数据才能比对像素与断言数值 |
| 原型（单文件 HTML） | 允许 | 原型不是产品，数据是演示用的 |
| 预览、演示、任何部署给他人使用的实例 | **禁止** | 数据必须来自真实 CRP / Gerrit / Shuttle |

规则：

1. **部署启动不得自动灌种子数据。** 启动命令里不允许出现 `db:seed`。
2. **不设「开启才灌」的开关。** `SEED_ON_START=1` 这类设计不算解决办法，只要代码路径存在就会有人打开。种子只允许出现在测试脚本与 CI 里。
3. **部署实例上检测到种子特征要报出来。** 种子数据有可识别的特征（固定的工作区名、固定的四条基线、固定的账号邮箱），启动自检发现就写错误日志并以非零退出，不允许静默带着假数据对外服务。
4. **界面验收在实机环境做。** 验收人看到的就是真实数据；报告里要写明数据来源。

## 二、调度

平台自己维护定时任务，不依赖宿主 cron 或 systemd timer。

### 形态

- **独立 worker 进程**：`pnpm worker`。与 web 同一镜像、不同启动命令。
- 作业在 worker 内直接调用现有函数，**不走 HTTP**，避免自己请求自己、也避免把内部逻辑暴露成接口。
- 频率：

| 作业 | 频率 | 作用 |
| --- | --- | --- |
| `baseline-sync` | 每小时 | 刷新 CRP 交付分支清单与被项目选中的基线包版本 |
| `build-dispatch` | 每 2 分钟 | 把在跑的提测往前推一步 |
| `build-poll` | 每 5 分钟 | 回写 Shuttle 构建结果与 CRP 工作流进度 |

### 集群化

后续要支持多副本，所以调度必须从第一天就是集群安全的：

- 每轮执行前用 Postgres 咨询锁抢占：`pg_try_advisory_lock(<作业的固定键>)`。
- 抢不到就跳过这一轮，记一条「被其他实例占用」的日志，不排队、不重试。
- 锁必须在**同一条数据库连接**上持有到作业结束，结束即释放（`pg_advisory_unlock` 或关闭连接）。
- **不允许**用进程内布尔标记、文件锁、或者「只在启动时判断」代替咨询锁。多副本下这些全部失效。
- 三个作业各用不同的锁键，互不阻塞。

### 失败与观测

- 单轮失败只影响本轮，worker 进程不退出。
- 每轮写一条结构化日志：作业名、开始时间、耗时、结果、跳过原因。
- worker 启动与退出各写一条日志，用来判断进程是否活着。
- 三个 HTTP 接口保留，供手动触发与排障；worker 不依赖它们，删掉它们也不影响调度。

### 迁移

worker 上线后，RUNBOOK 第五节从「必须配宿主 cron」改为「部署时同时起 web 与 worker」，并删掉 crontab / systemd timer 的示例。

## 三、验收

| 编号 | 验收内容 | 验证方式 | 通过条件 |
| --- | --- | --- | --- |
| RT-1 | 多实例不重复执行 | 起两份 worker 指向同一个库，观察一轮 | 同一时刻只有一个实例执行同一作业；另一个日志里写「被占用跳过」 |
| RT-2 | worker 可独立存活 | 停掉 worker | 作业不再执行，web 仍可正常访问 |
| RT-3 | 部署不灌种子 | 检查容器启动命令与启动后的库 | 命令里没有 `db:seed`；库里没有种子特征 |
| RT-4 | 种子自检 | 在一个灌了种子的库上启动部署实例 | 启动自检报错并以非零退出 |
| RT-5 | 手动触发仍可用 | 单独 POST 三个作业接口 | 都能正常执行 |
| RT-6 | 单轮失败不拖垮进程 | 让某个作业抛错 | worker 继续跑下一轮，日志有失败原因 |
